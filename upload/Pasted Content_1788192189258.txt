### 2.2 The 3D Illusion (Critical to Study)

Subway Surfers is a 3D game (Unity). Since we are using LibGDX (2D engine), we must replicate the 3D FEEL using 2D rendering techniques. Here is exactly what Subway Surfers does visually:

**Camera:**
- The camera is positioned **behind and above** the character at roughly a 30-45 degree angle
- The camera looks forward along the track, slightly downward
- The vanishing point is at approximately **35-40% from the top of the screen**
- Three railway tracks are clearly visible, converging toward the vanishing point
- The character occupies roughly the **lower 30-40%** of the screen

**Perspective:**
- Objects further away (higher Z) are rendered **smaller** and **closer together** (lane width narrows with distance)
- Objects further away are **slightly bluer/desaturated** (atmospheric perspective/fog)
- The ground plane (tracks, ground) is rendered as a **receding surface** — rails converge to vanishing point
- Buildings and environment objects on the sides scale with distance

**Depth/Speed Communication:**
- The world rushes toward the camera — this is the primary speed communication
- Parallax layers at different scroll rates create depth
- Track sleepers/ties rush past, creating a strong sense of forward motion
- Distant objects move slowly, near objects move fast — classic parallax
- Speed lines or motion blur at very high speeds

**For Dummy Surfers by FSK:** Replicate ALL of the above using LibGDX SpriteBatch with manual perspective math. Every object's screen position and scale must be calculated from its world Z-position using perspective division. This is the single most important visual technique.

## 4. VISUAL QUALITY — THE #1 PRIORITY

### The "Ugly" Problem

Previous attempts at this game failed visually because:
- Flat rendering with no depth/perspective
- No parallax — background was static
- Choppy animations — character teleported between positions
- Empty environment — bare tracks, no buildings or detail
- Coins didn't animate — static yellow circles
- Trains looked like colored rectangles
- UI looked like a Flutter tutorial, not a game

### The Solution — Pseudo-3D Perspective Rendering

Every frame must communicate speed, depth, and life. The rendering approach:

```kotlin
// Core perspective math — apply to EVERY game object
fun worldToScreen(worldX: Float, worldY: Float, worldZ: Float): ScreenPos {
    val scale = baseScale / (1.0f + worldZ * perspectiveFactor)
    val screenX = vanishingPointX + (worldX - cameraX) * scale
    val screenY = vanishingPointY + (worldY - cameraY) * scale
    return ScreenPos(screenX, screenY, scale)
}
```

- `perspectiveFactor` controls how quickly objects shrink (tunable in GameConfig)
- `vanishingPointY` at ~38% from top of screen
- All objects are **z-sorted back-to-front** before rendering
- Distant objects get **atmospheric fog** (blend toward sky color)
- Lane width **narrows with distance** (tracks converge to vanishing point)
- Ground plane rendered as **receding trapezoids**

### 7-Layer Parallax (MANDATORY)

| Layer | Content | Scroll Speed | Visual Purpose |
|-------|---------|-------------|---------------|
| 1 — Sky | Gradient sky + clouds | 0.02x | Atmosphere |
| 2 — Skyline | City silhouette | 0.08x | Location establishment |
| 3 — Mid Buildings | Building facades | 0.20x | Depth mid-ground |
| 4 — Near Buildings | Close buildings, stations | 0.40x | Structural detail |
| 5 — Railway | Bridges, platforms, wires | 0.60x | Track infrastructure |
| 6 — Track | Rails, sleepers, equipment | 0.85x | Immediate ground |
| 7 — Foreground | Poles, signs, dust particles | 1.00x | Speed + close detail |

### Environment Density (MANDATORY)

The world MUST include ALL of these at all times:
- Railway tracks with proper perspective (converging rails + sleepers)
- Overhead catenary wires and support poles

### Jump Math
```
jumpHeight(t) = jumpStrength * sin(PI * t / jumpDuration)
// jumpDuration: 0.6s, jumpStrength: 4.0 units (tunable)
```
- Parabolic arc with slight hang time at peak
- Landing squash animation
- Jump buffer: 100ms queue for landing

### Slide Mechanics
- Duration: 0.5s
- Collision box reduces to 40% height
- Roll animation
- Can jump out of slide early

### Swipe Detection
```
touchDown: record startX, startY, startTime
touchUp:
  dx = endX - startX, dy = endY - startY
  distance = sqrt(dx*dx + dy*dy)
  if distance < 15px: IGNORE
  if dt > 300ms: IGNORE
  if abs(dx) > abs(dy): SWIPE LEFT or RIGHT
  else: SWIPE UP or DOWN
```
- Input latency: <16ms
- One swipe = one action
- Dead zone: 15px

### Camera
- Behind-and-above the player, ~35 degree angle
- Vanishing point at 38% from top
- Smooth follow with lerp factor 0.1
- Slight camera shake on near-miss with trains
- Subtle zoom-out during boost power-up

## 6. PROCEDURAL WORLD GENERATION

### Obstacle Pattern System (CRITICAL — NO IMPOSSIBLE COMBINATIONS)

**IRON RULES:**
1. At least 1 lane MUST always be clear
2. 2-lane obstacles leave exactly 1 safe lane
3. Low obstacles: jumpable path exists
4. High obstacles: slideable path exists
5. Moving trains: 1.5s+ reaction time at current speed
6. Coins guide player toward safe path
7. Never place two same-action obstacles consecutively with <0.5s gap

**Pattern Examples:**
- EASY: Single train left lane, center+right clear
- MEDIUM: Train left+right, center only option + coin trail leading to center
- HARD: Low barrier center + high barrier left + train approaching right — requires slide center, jump over low barrier, or dodge to right before train arrives
- ADVANCED: Moving train center, requiring timed lane switch through the gap

### Difficulty Progression

```
currentSpeed = baseSpeed + (maxSpeed - baseSpeed) * (1 - e^(-distance * accelFactor))
```

| Phase | Distance | Speed | Obstacle Frequency |
|-------|----------|-------|-------------------|
| Start | 0-200m | 55% max | Every 40-60m |
| Early | 200-800m | 65% | Every 25-40m |
| Mid | 800-2000m | 78% | Every 15-25m |
| Late | 2000-4000m | 88% | Every 10-18m |
| End | 4000m+ | 95-100% | Every 8-12m |
